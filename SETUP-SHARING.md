# Making gallery uploads visible to everyone

Right now anything a member uploads is saved **on their own phone only**. The app
says so in an orange banner at the top of the gallery.

The reason is simple: this app is a single HTML file served by GitHub Pages.
There is no server behind it, so there is nowhere to put a file that other
people's phones can read. Shared uploads need storage outside the app.

Pick **one** of the two options below. Option A is the easier one.

---

## Option A — Cloudinary (recommended, ~5 minutes)

Only two public values are needed. No database, no SQL.

1. Sign up free at <https://cloudinary.com>
2. On the dashboard, copy your **Cloud name** (something like `dxy12abcd`)
3. Go to **Settings → Upload → Upload presets → Add upload preset**
   - Set **Signing mode** to **Unsigned**
   - Under **Allowed formats**, restrict it to images and video
   - Save, and copy the **preset name**
4. Go to **Settings → Security** and tick **Resource list**
   (this is what lets the app read the gallery without a secret key)
5. Send me the two values, or edit `docs/index.html` yourself and fill in:

```js
const CLOUDINARY_CLOUD='your-cloud-name';
const CLOUDINARY_PRESET='your-unsigned-preset';
```

That is all. Every upload from anyone then goes to the shared gallery.

**Two things to know**
- Cloudinary states that unsigned uploads can be abused, since anyone reading
  the page can use the preset. Restricting the preset to images and video keeps
  the damage limited. For a fellowship app this is a fair trade.
- Deleting a shared file has to be done from the Cloudinary dashboard. Removing
  it from inside the app would need a secret key, and a secret cannot be shipped
  in a public page.

## Option B — Supabase (if you prefer a real database)

1. Sign up free at <https://supabase.com> and create a project
2. **Storage → New bucket** named `gallery`, marked **Public**
3. **SQL Editor** and run this:

```sql
create table uploads (
  id bigint generated by default as identity primary key,
  type text, name text, size bigint,
  url text, path text, by text,
  "addedAt" bigint
);

create table hymns (
  id text primary key,
  number text, title text, author text,
  lyrics text, by text,
  "addedAt" bigint
);

alter table uploads enable row level security;
alter table hymns   enable row level security;

create policy "read uploads"  on uploads for select using (true);
create policy "write uploads" on uploads for insert with check (true);
create policy "read hymns"    on hymns   for select using (true);
create policy "write hymns"   on hymns   for insert with check (true);
```

4. **Settings → API**, copy the **Project URL** and the **anon public** key
5. Send them to me, or fill in:

```js
const SUPABASE_URL='https://xxxxx.supabase.co';
const SUPABASE_ANON_KEY='eyJ...';
```

The anon key is meant to be public; row level security is what protects the
data. The policies above allow anyone to read and add, which suits a fellowship
gallery. Tighten them later if needed.

---

## Which to choose

| | Cloudinary | Supabase |
|---|---|---|
| Setup | 2 values, no SQL | bucket + 2 tables |
| Free tier | generous for photos | 1 GB |
| Delete from app | no | yes |
| Hymn sharing | photos/videos only | photos, videos **and** hymns |

If you want **uploaded hymns** shared as well, use Supabase. Cloudinary covers
photos and videos.

---

## Long videos

Neither option suits a 600 MB service recording. Put those on YouTube as
**Unlisted** and add the link — the app already plays them inline, full screen,
with swipe between videos.
